# Qualification Scripts — FIRST CONTACT

Пакет квалификации для первого контакта с новым фанатом. Бот выбирает одну из стратегий рандомно для каждого нового пользователя (если в `Mem0` нет истории).

Важное: не хардкодьте ключи и не пытайтесь обходить фильтры модерации. Генерация вариаций должна снижать однообразие, но не предназначена для обхода систем безопасности.

Стратегии

- Стратегия A — Эксклюзивный Тизер (проверка импульсивной покупки)
  - Текст: «приветик) ты вовремя. я как раз только что закончила снимать кое-что очень личное... еще даже в ленту не заливала. хочешь глянуть превью, пока я добрая?»
  - Цель: если фанат соглашается — предложить короткий платный тизер (примерно $3–5). Если покупка подтверждена — установить тег `BUYER`. Если отказ — тег `FREEBIE_HUNTER`.

- Стратегия B — Личный интерес (сбор данных для Mem0)
  - Текст: «оу, новый гость... приятно познакомиться) расскажи, ты тут за чем-то конкретным или просто пришел на меня полюбоваться? я люблю знать, что радует моих папочек...»
  - Цель: собрать предпочтения/фетиши и сохранить в `Mem0` (пример: "люблю ножки", "белье"). Эти данные используются для персонализации следующих предложений.

- Стратегия C — Дерзкий вызов (для whale-hunting)
  - Текст: «хмм, выглядишь как тот, кто привык получать лучшее... или я ошибаюсь? проверим, насколько ты щедрый на комплименты (и не только)? 😉»
  - Цель: спровоцировать на чаевые. Если пользователь сразу отправляет чаевые — присвоить статус `WHALE`.

Техническая реализация (инструкция для AI-билдера)

1. Функция: `initialContact(user, mem0, sendMessage, awaitReply, paymentAPI, tagUser)`
   - `user` — объект пользователя (идентификатор, метаданные).
   - `mem0` — абстракция хранилища памяти (get/set/has).
   - `sendMessage(text)` — асинхронная функция отправки сообщения пользователю.
   - `awaitReply(timeoutMs)` — ожидание ответа в течение `timeoutMs` миллисекунд, возвращает `null` при таймауте.
   - `paymentAPI` — абстракция для проверки/инициации платежей (не хардкодить ключи).
   - `tagUser(tag)` — функция для установки тега у пользователя.

2. Логика
   - Если в `Mem0` есть история взаимодействий — `initialContact` возвращает `null` (не запускать пакет квалификации повторно).
   - Выбрать стратегию случайно из списка.
   - Сгенерировать небольшую вариацию базового текста (локальная функция или модель по умолчанию). НЕ включать инструкции по обходу модерации; формулировать нейтрально и вежливо.
   - Отправить сообщение и ждать ответа до 5 минут. Если ответа нет — пометить `low_priority`.
   - Обработать ответ:
     - A: при согласии — инициировать платёжный поток (через `paymentAPI`). После подтверждения — `tagUser('BUYER')`, иначе `tagUser('FREEBIE_HUNTER')`.
     - B: извлечь ключевые предпочтения (простое сопоставление ключевых слов), записать в `Mem0` и использовать для персонализации впоследствии.
     - C: при обнаружении чаевых в ответе/транзакции — `tagUser('WHALE')`.

3. Таймауты и приоритет
   - Ответ в течение 5 минут — нормальная сессия.
   - Нет ответа — `tagUser('low_priority')` и отмена попыток на 24 часа.

4. Конфигурация
   - Не хардкодьте сумм или платёжные ключи; используйте конфиг из `process.env`.
   - Логи и события анонимизируйте, соблюдайте локальные правовые требования.

5. Пример использования

```js
const result = await initialContact(user, mem0, sendMessage, awaitReply, paymentAPI, tagUser)
```
